# lifehacker.dev

> Surviving life, one byte at a time. Knowledge, tools, and comedy — published by a robot, reviewed by a human, shipped with the mistakes left in.

## Overview

A [Jekyll](https://jekyllrb.com/) site rendered by the [`bamr87/zer0-mistakes`](https://github.com/bamr87/zer0-mistakes) **remote theme** and served by **GitHub Pages** at the apex domain `lifehacker.dev`. It is also a **headless CMS driven by [Claude Code](https://claude.com/claude-code)**: the brand, the content queue, the ledgers and the site's health all live in this repository as data files, the robot opens pull requests against them, and a human merges every one — see the [autopilot operator's guide](docs/AUTOPILOT.md).

## Features

- Four news sections — Hacks, Tools, Field Notes and The Wire — with pinned permalinks under `/hacks/`, `/tools/` and `/wire/`
- The Wire, a sourced news desk bound by a press charter: satire in the framing, never the facts
- The zer0-mistakes remote theme with a neon skin configured in `_config.yml`
- A Claude Code autopilot that drafts, reviews and ships content ([docs/AUTOPILOT.md](docs/AUTOPILOT.md))
- Offline cover art and figures generated by scripts in `scripts/`
- A CI harness that runs a Pages safe-mode build plus front-matter, brand, drift and link lints

## Quick start

```bash
bundle install          # deps: github-pages + html-proofer (Gemfile.lock is committed on purpose)
scripts/preview.sh      # overlay onto a theme clone + docker compose up → http://localhost:4000
scripts/ci/run-all.sh   # the full harness: green here == green `verify`
```

The preview needs Docker: this repo has no local layouts, so `scripts/preview.sh` overlays the content onto a clone of the theme and serves that. In VS Code the same runs are one click away under **Terminal → Run Task** ([`.vscode/tasks.json`](.vscode/tasks.json)): `Serve` the preview, `Verify` reproduces the `verify` gate (safe-mode build + harness, in Docker), `Author: preview image` draws cover art for the article you have open, and the `Claude:` tasks hand the harness findings to a Claude Code role. **Run & Debug** ([`.vscode/launch.json`](.vscode/launch.json)) attaches Edge DevTools to the preview or the live site. Every repo in the fleet carries the same layout — the convention is written down in [`.vscode/README.md`](.vscode/README.md).

## Why the config is hand-written, not copied

`remote_theme` only delivers the theme's `_layouts/`, `_includes/`, `_sass/`, and `assets/`. It does **not** deliver the theme's `_config.yml`, `_data/`, or `_plugins/`. So this repo deliberately re-declares everything the theme's layouts expect, and ships its own `_data/`. (Copying the theme's `_config.yml` wholesale would also inherit the theme author's analytics keys — don't.) The [Field Notes](https://lifehacker.dev/news/field-notes/) tell that story with jokes.

## The autopilot

This site grows itself: Claude Code reads `_data/brand/` + `_data/backlog.yml`, drafts on-voice content with screenshots, files theme bugs upstream, and opens a PR. **A human reviews and merges every change.** Every autonomy loop idles until its `*_ENABLED` repository variable is turned on. Full design in [docs/AUTOPILOT.md](docs/AUTOPILOT.md) and at [/docs/autopilot/](https://lifehacker.dev/docs/autopilot/).

## Git With the Program

[Git With the Program](https://lifehacker.dev/news/git-with-the-program/) turns repository evidence into entertaining Field Notes, not invented incident reports. Its contract is [`_data/campaigns/git-with-the-program.yml`](_data/campaigns/git-with-the-program.yml); how to prepare an evidence bundle, draft, check and hand a draft to human review is in [docs/GIT-WITH-THE-PROGRAM.md](docs/GIT-WITH-THE-PROGRAM.md).

## Project structure

| Path | What it is |
|---|---|
| `_config.yml` | The whole site config — identity, neon skin, collections, defaults, plugins. |
| `_config_dev.yml` | Local-preview overlay (disables `remote_theme` so builds use local theme files). |
| `zer0.json`, `.theme-overrides.yml` | zer0 stack config: the zer0-CMS content model (folders, content types, required fields) and the theme files this site forks on purpose (none). `.github/workflows/zer0-doctor.yml` checks the contract. |
| `_data/navigation/`, `authors.yml`, `landing.yml` | Site data the remote theme needs but does **not** deliver. |
| `_data/brand/` | The machine-readable brand: `identity.yml`, `voice.yml`, `glossary.yml`. The autopilot reads these. |
| `_data/campaigns/` | Editorial campaign contracts consumed by external drafting tools; `git-with-the-program.yml` governs evidence-grounded repository histories. |
| `_data/backlog.yml` | The autopilot's content queue. |
| `_data/wire/` | The Wire's assignment editor (`sources.yml`: news sources, frequencies, trust tiers, filters) + the crawl trail the `wire-scout` loop writes. The press charter it answers to lives in `_data/brand/identity.yml`. |
| `pages/_posts/` `_about/` `_docs/` | Content collections (under `pages/` because `collections_dir: pages`). `_posts/` splits into `hacks/`, `tools/`, `field-notes/`, `wire/` — the news sections. |
| `pages/news/` | The `/news/` landing pages (`index.md` + one per section). |
| `pages/*.md`, `pages/search.json` | Loose site pages: the `search`/`sitemap`/`tags`/`categories`/`concepts` utilities, plus the `blog`/`hacks`/`tools`/`wire` redirect stubs that keep old URLs resolving to their `/news/` homes. `search.json`/`sitemap.md` are hand-authored because the theme's generator is a plugin that GitHub Pages won't run. |
| `index.md`, `404.html` | The only two site pages left at the repo root — the ones GitHub Pages wants there. |
| `scripts/` | The test harness (`ci/`), the pipeline audit (`devops/`), cover art (`preview/`, `media/`) and the fleet's loops; `scripts/preview.sh` is the local Docker preview. |
| `.claude/` | The agents and skills the fleet runs; `.claude/skills/grow-lifehacker/` is the autopilot skill. |
| `docs/` | Operator docs, excluded from the site build — indexed in [docs/README.md](docs/README.md). |
| `mcp/` | The read-only `lifehacker-read` MCP server ([README](mcp/lifehacker-read/README.md)). |

## Development

```bash
bundle install
scripts/ci/run-all.sh     # the same gates CI runs
```

GitHub Pages builds the real site from `main` on push. Pull requests are gated by the `verify` job of [`.github/workflows/pipeline.yml`](.github/workflows/pipeline.yml), which reproduces the Pages build in safe mode and lints content, links, drift, and brand voice. The checks live in [`scripts/ci/`](scripts/ci/) and run identically for humans (`scripts/ci/run-all.sh` or the `/test-lifehacker` skill) and in CI. A human still merges every PR — branch protection + [`CODEOWNERS`](.github/CODEOWNERS) enforce it. See [`docs/runbook-fleet.md`](docs/runbook-fleet.md) for setup.

Full commands, conventions and gotchas for humans and AI agents live in [AGENTS.md](AGENTS.md).
